# 도시의 한 사람 — 온라인 멀티플레이 프로토타입 0.2

## 구현된 기능
- 방 생성 및 6자리 방 코드 입장
- 방당 최대 12명
- 플레이어별 이름과 무작위 출생지/가정환경/초기 능력치
- 모든 플레이어가 공유하는 날짜, 도시 사건, 사건 진행 기록
- 개인별 하루 3회 행동
- 모두 행동을 마치면 다음 날 진행
- 실시간 플레이어 목록과 채팅
- 무작위 도시 사건 및 간단한 사건 선택
- 서버 메모리 기반 방 상태

## 실행 방법
1. Node.js 18 이상 설치
2. 이 폴더에서 터미널 실행
3. `npm install`
4. `npm start`
5. 브라우저에서 `http://localhost:3000` 접속

같은 와이파이의 다른 기기에서 접속하려면 서버를 실행한 컴퓨터의 로컬 IP 주소와 `:3000`을 사용하세요. 방화벽에서 3000 포트 접속을 허용해야 할 수 있습니다.

인터넷을 통해 서로 다른 장소의 사용자가 접속하려면 서버를 공개 호스팅에 배포해야 합니다. 이 압축 파일만으로 공개 서버가 자동 생성되거나 배포되지는 않습니다.

## 프로토타입 한계
- 방과 캐릭터 데이터는 서버 메모리에만 저장됩니다. 서버를 재시작하면 초기화됩니다.
- 인증, 계정, 영구 저장, 운영자 도구, 신고/차단, 치트 방지 기능은 아직 없습니다.
- 사건은 규칙과 텍스트 조합으로 생성되는 초기 버전입니다. 장기 기억을 가진 복잡한 NPC 시뮬레이션은 다음 단계입니다.
- 프로젝트 문 공식 원문/캐릭터/대사를 복제하지 않는 비공식 팬 프로젝트용 독자 텍스트 프로토타입입니다.

## GitHub + Render로 공개 배포하기

이 프로젝트에는 Render 배포 설정(`render.yaml`)이 포함되어 있습니다.

1. GitHub에서 새 저장소(repository)를 만듭니다. 예: `city-life-multiplayer`
2. 이 프로젝트 폴더 안의 파일(`package.json`, `server.js`, `public/`, `render.yaml`, `README.md`, `.gitignore`)을 저장소에 업로드합니다. 폴더 자체를 한 겹 더 중첩해서 올리지 않도록 주의하세요.
3. Render에 가입한 뒤 **New → Blueprint**를 선택하고 방금 만든 GitHub 저장소를 연결합니다.
4. Render가 `render.yaml`을 읽으면 서비스를 생성합니다. 배포가 끝나면 Render가 제공하는 `https://...onrender.com` 주소로 접속합니다.
5. 친구들에게 같은 주소를 보내면 각자 접속한 뒤 방 코드를 공유해 함께 플레이할 수 있습니다.

주의: GitHub Pages는 정적 웹사이트 호스팅이라 이 프로젝트의 Socket.IO 서버를 실행할 수 없습니다. Render 같은 Node.js 호스팅이 필요합니다. 무료 서비스는 일정 시간 사용하지 않으면 잠들 수 있고, 서버가 재시작되면 현재 프로토타입의 방/캐릭터 데이터가 초기화됩니다.
